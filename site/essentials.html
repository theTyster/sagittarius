1 of 10 · The problem

The wrong-spec problem

An agent can build exactly what it was told, and still build the wrong thing.

An agent is an AI that does the work, such as Claude Code. A spec is what it builds from: the request, the ticket, and the tests.

Wrong

The spec does not match how things really are.

Incomplete

The spec leaves out a case that matters.

Read two ways

The human and the agent read the same words and see different things.

The human is the source of intent. The human is not always the source of clarity.

7 of 10 · The tool

What it is

The prompt
One plain-text file, appended to the agent's system prompt. It says how to work: start light, shift up on a signal.
orbit-kb
A command-line tool that keeps the knowledge base (KB): every fact declared, typed, and checked.
Prolog
SWI-Prolog 9 or later with s(CASP): answers the KB's questions.
Lean 4
Only for proofs. Install with elan. Optional helpers: sharlean (shared libraries such as Mathlib) and lean-lsp-mcp.

8 of 10 · The tool

How to use it

You rarely type orbit-kb yourself. Most requests stay on the light path: one check, no KB.

Install on Fedora
$ sudo dnf install swi-prolog-nox
$ swipl -g "pack_install(scasp, [interactive(false)])" -t halt
$ ln -s ~/.local/share/swi-prolog/pack/scasp/scasp ~/.local/bin/scasp
$ orbit-kb doctor

For orbit-kb prove, install Lean 4 and Lake with elan. Ty's Lean projects share their libraries through sharlean, so a proof does not rebuild Mathlib. In Ty's dotfiles, create-links puts orbit-kb on the PATH and its rules in ~/.local/share/orbit-kb.
